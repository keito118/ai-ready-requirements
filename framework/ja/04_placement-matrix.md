## ID の付け方

| 接頭辞 | 意味 |
|---|---|
| `REQ-` | ヒアリングで出てきた元の要望（1件の要望に1つ） |
| `APP-` | アプリ / AI 層に置く要件 |
| `ONT-` | オントロジー層に置く要件（オブジェクト・ロジック） |
| `SEM-` | セマンティック層に置く要件（ロジックを実装するビュー） |
| `DAT-` | データ層に置く要件 |
| `POL-` | ポリシー（横断）に置く要件。誰が何を見てよいか・してよいか |

## 4. 振り分けチェックリスト

- [ ] すべての `REQ-` が、少なくとも1つの層に振り分けられている
- [ ] 同じ意味・ルールが2つ以上の場所に書かれていない
- [ ] `APP-` の要件が、業務ルールや計算式を自分で持っていない（オントロジーを参照している）
- [ ] AI のプロンプトに書く予定の内容が、`ONT-` の参照だけになっている
- [ ] 判定・計算のロジックはすべて `SEM-` にバインドされ、`SEM-` はすべて実装するロジックを持っている
- [ ] 部門別の版があるロジックには、既定版がある
- [ ] 状態を持つオブジェクトに時点の定義がある
- [ ] 閲覧範囲と AI の実行可否は `POL-` で定義され、4つの層すべてで同じルールが効く
- [ ] 合計点が境界（8〜9点）の要件と、フローと点数が食い違った要件は、判断理由が書かれている
- [ ] すべての `ONT-` と `POL-` に決定権者が書かれている
