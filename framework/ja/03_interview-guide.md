# 03. ヒアリングガイド

> 業務担当者へのヒアリングで使う質問リストです。AI で実装が速くなるほど、要件定義の工数はヒアリングに寄っていきます。AI がプロンプトを処理する順番（アプリ / AI → オントロジー → セマンティック → データ）に沿って並べ、最後に横断するポリシーを聞きます。
>
> 進め方：最初に「0. 全体」を聞き、出てきた業務用語や数字ごとに 1〜5 を深掘りします。回答はそのまま [04 振り分けマトリクス](04_placement-matrix.md) の「元の要望」欄に書き写します。

## 0. 全体

| No | 質問 | 聞く理由 |
|---|---|---|
| G-01 | この業務で、最終的に誰が何を判断していますか | 判断に使う概念と数字を洗い出す起点 |
| G-02 | その判断のために、今どの資料・画面・数字を見ていますか | 既存の定義（の散らばり方）を把握する |
| G-03 | 判断を誤ったとき、何が起きますか | 「ブレたときの影響」の点数の根拠 |
| G-04 | AI に任せたい作業・任せたくない作業は何ですか | アプリ / AI 層の範囲と、AI が使う定義・ポリシーの洗い出し |

## 1. アプリ / AI 層（入口と出口）

| No | 質問 | こんな答えが出たら |
|---|---|---|
| A-01 | 誰が、どのタイミングで、どの端末で使いますか | 利用シーンと、受け取るユーザーコンテキスト（役割・部門） |
| A-02 | 一目で分かってほしいことは何ですか | 画面の優先順位、強調表示 |
| A-03 | 今いちばん手間がかかっている操作は何ですか | 自動化・AI 化の候補 |
| A-04 | AI の回答に、根拠として何が示されていれば信用できますか | 参照元の提示方法。参照先はオントロジーの定義であるべき |
| A-05 | AI が間違えたとき、誰がどう気づいて直しますか | 人による確認ポイント |

## 2. オントロジー層（意味）

> [06 オントロジー設計ガイド](06_ontology-design.md) の順番（オブジェクト → ロジック）に沿って聞きます。言葉がそろう前にルールを議論しないのがコツです。途中で足りない概念が出てきたら、オブジェクトの質問に戻ります。

| No | 要素 | 質問 | こんな答えが出たら |
|---|---|---|---|
| O-01 | オブジェクト | 業務でよく使う言葉を挙げてください。同じものを別の呼び方をしていませんか | 概念とラベル（同義語）の候補 |
| O-02 | オブジェクト | その言葉は部署によって意味が違いますか | 違うなら、別の概念に分けるか、部門を引数にしたロジックにする（最重要） |
| O-03 | オブジェクト | 「〇〇」に含まれないのはどんな場合ですか | 反例。AI の誤解を減らすのにいちばん効く |
| O-04 | オブジェクト | 業務で扱う「モノ」は何ですか。それぞれ、何をもって1件と数えますか | オブジェクトと、一意になる条件 |
| O-05 | オブジェクト | 〇〇と△△はどういう関係ですか。1対多ですか | 関係と多重度 |
| O-06 | オブジェクト | 〇〇にはどんな状態がありますか。何が起きると変わりますか | 状態と遷移。例外的な遷移（差し戻し、復活）も聞く |
| O-07 | オブジェクト | 「今の状態」とは、いつ時点のことですか（当日、前日末、月末） | 時点の定義 |
| O-08 | ロジック（判定） | 「〇〇かどうか」は、どう判断していますか。必ず守るルールはありますか。誰が決めましたか | 判定ロジックと決定権者 |
| O-09 | ロジック（計算） | よく見る数字を挙げてください。その数字は、言葉で言うと何を表していますか | 計算ロジックの説明文。式は 3. で聞く |
| O-10 | ロジック | 部門によって、判断の基準や数字の意味は変わりますか | 部門を引数にした版と、既定版 |
| O-11 | ロジック（操作） | 誰が、どんな条件のときに、何を変更・処理していますか | 操作ロジックの前提条件と結果 |
| O-12 | 共通 | そのルールや定義が前回変わったのはいつですか | 変更頻度と有効期間 |

## 3. セマンティック層（計算の実装）

> オントロジーで意味が決まった数字・判定について、計算の手順を聞きます。意味が決まっていない数字の式から議論しないでください。

| No | 質問 | こんな答えが出たら |
|---|---|---|
| S-01 | その数字は、何を足して・何を除いて・何で割っていますか | 集計式。税込 / 税抜、キャンセルの扱い、返品の扱いなど |
| S-02 | 「今月」とはいつからいつまでですか | 期間の扱い（暦月 / 会計月 / 締め日） |
| S-03 | その数字をどんな切り口・単位で見ますか（地域別、担当別、日次・週次…） | 集計軸と粒度 |
| S-04 | 同じ名前で、部署ごとに違う数字が出ていませんか | 定義の分裂。まず O-02・O-09 で意味をそろえてから実装する |

## 4. データ層（値の出どころ・鮮度・品質）

| No | 質問 | こんな答えが出たら |
|---|---|---|
| D-01 | そのデータは、どのシステム・誰の入力から来ていますか | ソースと入力責任者 |
| D-02 | どれくらい新しいデータが必要ですか（リアルタイム、前日、月次） | 取り込み頻度 |
| D-03 | データが間違っていたり、抜けていたりすることはありますか | 品質ルールの候補 |
| D-04 | 過去の状態（変更前の値）を見たいことはありますか | 履歴の持ち方 |
| D-05 | いつまで残す必要がありますか。消さないといけないデータはありますか | 保持期間、個人情報の扱い |

## 5. ポリシー（横断）

| No | 質問 | こんな答えが出たら |
|---|---|---|
| P-01 | その情報や数字を見てよい人・見てはいけない人は誰ですか | 行・列レベルの閲覧範囲。AI 経由でも同じ範囲にする |
| P-02 | その処理を AI に任せてよいですか（自動 / 人が確認してから / 任せない） | 操作ロジックの AI 実行可否 |
| P-03 | AI に渡してはいけない情報はありますか（個人情報など） | マスキングの対象 |

## ヒアリング中に注意するサイン

| サイン | 意味 | 次に聞くこと |
|---|---|---|
| 同じ言葉を人によって違う意味で使っている | オントロジーが未定義 | O-02、O-03、O-08 |
| 「この画面の数字は、あの資料と少し違う」 | 数字の意味か計算の実装が分裂している | O-09 で意味を確かめてから S-01、S-04 |
| 「毎回 Excel で手直ししてから使う」 | データ層の品質問題をアプリ側で吸収している | D-03 |
| 「AI にはこう指示している」と業務ルールを語る | ルールがプロンプトに埋まっている | O-08 でロジックとして取り出し、AI に任せる範囲は P-02 で確認する |
| 「とりあえず画面に出してほしい」 | 意味が決まらないまま見せ方の話になっている | O-09 に戻る |
