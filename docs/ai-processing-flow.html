AI-Ready Requirements · 処理の流れ

AI が質問を処理する流れ

AI は質問を受け取ると、意味 → 数え方 → 権限 → 値 の順に具体化して答えます。各段階で読む層が決まっていて、どこかで定義が足りないと、回答を説明できなくなります。

全体の流れ

説明できない＝定義の穴
質問・依頼
受け取る自然言語のまま
「渋谷店の先月のアクティブ会員の退会率は？」
オントロジーONT
1. 解釈する言葉を正式な概念に置き換え、質問の種類と時点を決める
出力概念 ID（アクティブ会員・退会・店舗）、種類＝数字、時点＝先月末
セマンティックSEM
2. 数え方を選ぶ定義済みの指標と切り口から選ぶ
出力指標＝退会率、切り口＝店舗、期間＝先月
ポリシーPOL
3. 範囲を絞る質問した人の権限を、AI がそのまま引き継ぐ
出力店舗長なので渋谷店のみ取得可
データDAT
4. 取得する値と一緒に、鮮度と品質の情報も受け取る
出力退会率 3.1%、先月分は確定済み、品質エラー 0 件
回答ANS
5. 説明するオントロジーの言葉で説明し、データの注意点を添える
「先月の渋谷店の退会率は 3.1% です。先月末に確定した退会を、月初の在籍会員（休会を除く）で割っています」
戻り道：オントロジーの言葉で説明できなければ、どこかの定義が足りないサイン

質問の種類で、通る層が変わる

AI は毎回すべての層を通るわけではありません。1件の判定や操作は集合を計算しないので、セマンティック層を通りません。権限（ポリシー）は、値に触れるすべての経路で通ります。

質問の種類1. 解釈
ONT		2. 数え方
SEM		3. 範囲
POL		4. 取得
DAT		5. 説明
ANS
定義を聞くアクティブ会員って何？———
1件を聞く山田さんは今月退会できる？—
数字を聞く先月の退会率は？
理由を聞くなぜ退会率が上がった？
操作を頼むこの会員を休会にして—

「理由を聞く」は、数字を切り口ごとに分解したうえで、オントロジーの事象（入館の減少、退会申請など）の言葉で説明します。「操作を頼む」は、オントロジーのアクション定義で AI に許可されているか（自動 / 人の確認後 / 禁止）を確かめてから書き込みます。

各段階で AI が守ること

それぞれの層について、AI がしてよいこと・してはいけないことを1つずつ決めておくと、AI の振る舞いが揃います。

1. 解釈：オントロジー

語彙を索引にして、関係する部分だけ取り出す
オントロジー全体をプロンプトに入れる。意味を推測で補う
オントロジーは大きくなるため、全部を読ませると精度が落ちます。候補が複数あれば聞き返します。

2. 数え方：セマンティック

定義済みの指標と切り口から選ぶ
SQL や計算式をその場で書く
AI が式を書くと、同じ質問でも毎回違う数字になり得ます。定義にない質問には「未定義」と答え、新しい指標の案を出します。

3. 範囲：ポリシー

取得の時点で権限を強制する
「見せないで」とプロンプトでお願いする
プロンプトでの指示は破られることがあります。見てはいけない値は、そもそも AI に渡らないようにします。

4. 取得：データ

値と、いつ時点か・欠損や品質エラーをセットで受け取る
値だけを受け取って答える
鮮度を知らない AI は、古い数字を自信を持って答えてしまいます。

5. 説明：回答

オントロジーの言葉で説明し、使った定義と注意点を示す
定義に出てこない言葉で、もっともらしく説明する
説明できないときは、無理に答えず「定義の穴」として記録します。

戻り道：回答がオントロジーを鍛える

AI が説明に詰まった箇所は、そのまま要件定義の宿題になります。運用するほど定義が埋まっていく循環です。

質問「アクティブ会員の退会率は？」
→
詰まるいつ時点でアクティブだった人か、定義がない
→
仮の回答既定の時点で答え、その前提を明記する
→
記録未決事項として業務オーナーに確認する
→
定義を追加オントロジーに時点の定義が入り、次からは詰まらない
